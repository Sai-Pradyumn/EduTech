# Deploying Asta

**Backend (NestJS) → Render · Frontend (Angular) → Vercel · CI/CD → GitHub Actions**

## Why not "just GitHub Actions"?

GitHub Actions **runners are ephemeral CI compute** — a fresh VM spins up, runs your job
for a few minutes, then is destroyed. It can *build, test, and trigger* a deploy, but it
cannot *host* a long-running web app. (A "self-hosted runner" doesn't change that — it just
means you supply your own always-on machine for the runner to live on, i.e. you'd still need
a server.) So hosting goes to **Render** (backend) and **Vercel** (frontend); GitHub Actions
([deploy.yml](.github/workflows/deploy.yml)) is the gate + trigger.

```
push → GitHub Actions (build + test gate)
                │
        ┌───────┴────────┐
        ▼                ▼
  Render deploy     Vercel deploy
  hook (backend)    hook (frontend)
        │                │
   asta-api.onrender    asta.vercel.app
        │  ▲                │
        │  └── CORS ────────┘  (CLIENT_ORIGIN = Vercel URL)
        ▼
   MongoDB Atlas (free M0 replica set)
```

| File | Purpose |

## One-time setup

### 1. MongoDB Atlas (database)
Render has no MongoDB, and Asta wants a replica set (change streams + transactions).
1. Create a **free M0 cluster** at <https://cloud.mongodb.com> (it's a 3-node replica set).
2. Database Access → add a user. Network Access → allow `0.0.0.0/0` (Render has no static IP on free).
3. Copy the **SRV connection string**, e.g.
   `mongodb+srv://USER:PASS@cluster0.xxxx.mongodb.net/asta?retryWrites=true&w=majority`.

### 2. Render (backend)
1. <https://dashboard.render.com> → **New → Blueprint** → connect this repo → **Apply**
   (Render reads [render.yaml](render.yaml) and creates `asta-api`).
2. On the service → **Environment**, set the `sync:false` vars:
   - `MONGO_URI` = the Atlas string from step 1
   - `CLIENT_ORIGIN` = your Vercel URL (fill in after step 3, e.g. `https://asta.vercel.app`)
   - *(optional, to go live)* AI keys (`GROQ_API_KEY`, `GEMINI_API_KEY`, …), `RAZORPAY_KEY_ID`/
     `RAZORPAY_KEY_SECRET`, `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`, `GOOGLE_CLIENT_ID`. Unset → mock.
   `JWT_SECRET` / `JWT_REFRESH_SECRET` are auto-generated by the Blueprint.
3. Settings → **Deploy Hook** → copy the URL (used as `RENDER_DEPLOY_HOOK_URL` below).
4. Note your API URL, e.g. `https://asta-api.onrender.com`. Health check: `…/api/ops/health`.

### 3. Vercel (frontend)
1. <https://vercel.com> → **Add New → Project** → import this repo. Leave **Root Directory = repo root**
   (the [vercel.json](vercel.json) drives build/output).
2. Project → Settings → **Environment Variables** (Production):
   - `API_BASE_URL` = `https://asta-api.onrender.com/api`  *(your Render URL + `/api`)*
   - `SOCKET_URL`   = `https://asta-api.onrender.com`
3. Settings → Git → **Deploy Hooks** → create one for `main` → copy the URL
   (used as `VERCEL_DEPLOY_HOOK_URL` below).
4. After the first deploy, copy the Vercel domain and paste it back into Render's `CLIENT_ORIGIN`.

### 4. GitHub Actions secrets
Repo → Settings → Secrets and variables → **Actions** → New repository secret:
- `RENDER_DEPLOY_HOOK_URL` = from step 2.3
- `VERCEL_DEPLOY_HOOK_URL` = from step 3.3

(Until these exist, [deploy.yml](.github/workflows/deploy.yml) still runs the build/test gate and
just skips the deploy steps with a warning.)

## Day-to-day

```bash
git push origin main
```
→ GitHub Actions runs lint + build + tests, then pings both deploy hooks.
Render rebuilds the API; Vercel rebuilds the client. You can also trigger manually from the
**Actions** tab → *Deploy* → *Run workflow*.

## Notes & caveats
- **Free Render** cold-starts after ~15 min idle (first request after idle takes ~30–50 s).
- **File uploads** use local disk (`STORAGE_PROVIDER=local`), and Render's disk is **ephemeral**
  (wiped on every deploy/restart). For persistent uploads set `STORAGE_PROVIDER=s3` + the
  `AWS_*` / `S3_BUCKET` vars (see `server/.env.example`).
- **Redis/BullMQ** stays off (`ENABLE_BULLMQ` unset) — jobs run inline. Add a Redis (e.g. Upstash)
  and `ENABLE_BULLMQ=true` + `REDIS_HOST`/`REDIS_PORT` to enable the real queue.
- **CORS**: the API only accepts the origin in `CLIENT_ORIGIN`. If the browser console shows CORS
  errors, that var doesn't match your actual Vercel domain.
